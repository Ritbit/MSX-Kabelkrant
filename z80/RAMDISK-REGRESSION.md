# RAMdisk C: regression — integrated Z80 14-wipe Kabelkrant

**Status:** manual MSX runtime check; static disk packaging verified in CI.
This is a *separate* `KBLCTEST.DSK`, generated by copying the verified
`KBLWIPEINT14.DSK` and adding only one file, `CTEST.BAS`. The
original `AUTOEXEC.BAS`, RAMDISK.BIN, and LOOP.SYS are byte-identical.

## Test on WebMSX

Open:

https://webmsx.org/?MACHINE=MSX2E&RAMMAPPER_SIZE=256&AUTO_START=true&FAST_BOOT=1&DISK=https://raw.githubusercontent.com/Ritbit/MSX-Kabelkrant/feature/z80-renderer/assets/KBLCTEST.DSK

1. Let the newspaper start, confirming RAMdisk setup. Break to the
   BASIC prompt with Ctrl+Stop (on keyboards where this is awkward,
   use the WebMSX virtual keyboard / emulator controls).
2. Enter `RUN "A:CTEST.BAS"`.
3. Expected terminal line: `PASS: WRITE/READ/DELETE ON C:`.
   Any `FAIL` is a real runtime regression or environmental problem.

The test writes only `C:KBTST26.TMP`, reads back two deterministic
ASCII lines, compares exact content, then deletes the temporary file.
If the test fails before cleanup, that temporary filename may remain;
never use it for real content. An existing file with that exact name
would be overwritten. Do not reset between the write and read stages.

Once done, reset the emulated machine to restart normal Kabelkrant.
This test intentionally stops the broadcast; it is not integrated into
the startup sequence. It does not test other C: filenames, random-access
`GET`/`PUT`, or the editor, which remain separate checks.

## Automated gates

The workflow validates the test source's MSX BASIC ASCII encoding,
the test disk FAT12 structure, the exact encoded program, and byte
identity of **every other file** versus the original 14-wipe alpha.
The automated test **cannot** claim C: runtime success without running
on MSX. The optional openMSX smoke currently skips emulator execution
when the four private ROM secrets are absent.
